# Public API security-contract monitor

Hourly credential-free negative tests against the fixed public API only. The monitor covers all twelve current callable routes, including `acceptContentPolicy`, and both production SMS routes. Each route is tested with missing and invalid App Check tokens: 28 probes, at most four in flight, with no retries. No valid phone, OTP, user token, SMS send or authenticated mutation is used. Empty callable data and deliberately invalid SMS fixtures remain safe even if the attestation boundary regresses.

Requests have a 15-second total abort deadline, reject redirects, require JSON responses with `Cache-Control: no-store`, and cap response bodies at 4096 bytes. The expected response is HTTP 401 with the exact attestation rejection contract. Authorization errors that become cacheable, a missing consent route, proxy pages and transport failures all fail the monitor. Output excludes response bodies and exception text. Latency is observed, not a proven SLO.

The deployed-contract helper originated from app source `ec65e826e456f406a9087da843c4d4d6425d886d` and is maintained independently here. It is no longer a byte-identical copy. Current callable coverage was compared with app source `736d469c5b7b36be52bc31f2975431c38eb920e4`. This monitor does not deploy app source or inherit acceptance of another revision. A failing current public deployment must remain red; do not loosen expectations to match it. New callable routes require explicit safe fixtures and regression coverage. Legacy test OTP aliases and scheduled or Firestore triggers are outside the production-client route inventory.

GitHub Actions failure notifications follow the repository subscriber's settings; email receipt has not been tested. Scheduled runs depend on GitHub availability and may be delayed. This is not retention/backlog monitoring, authenticated two-user synthetic coverage, positive Store attestation or production certification. No paid services are enabled. PR runs exercise local monitor tests, not live endpoints. The schedule becomes active on the default branch only.
